# Implementation Order

Implement milestones sequentially.

## Phase A — Foundation

```text
M000 Product Contract
M001 Repository Foundation
M002 Knowledge Contract
```

At the end of Phase A, the repository is runnable and its core data is validated.

## Phase B — Core User Experience

```text
M003 Setup & Configuration
M004 Guide Resolution
M005 Prompt Generation
```

At the end of Phase B, openPrompting is already useful for real users.

## Phase C — Trust and Multi-model UX

```text
M006 Doctor
M007 Compare
M008 Profiles & Routing Hardening
```

At the end of Phase C, mixed-model workflows are first-class and local setup quality is inspectable.

## Phase D — Open-source Readiness

```text
M009 Contributor & Source Quality
M010 Release Candidate
M011 V1 Launch
```

At the end of Phase D, the package is stable enough to recommend publicly.

## Scope discipline

When a milestone exposes an attractive adjacent idea, ask:

> Is this required for the V1 user journey?

If no, put it in `99_POST_V1_BACKLOG.md`.

Do not let the following delay V1:

- website
- hosted docs app
- LLM integrations
- automatic handoffs
- harness-native slash command adapters
- prompt rewriting
- remote update service
- benchmark suite
